# Release Process

This document captures branching, semantic versioning, and GitHub release workflow.

## Branch naming

- `feat/<scope>-<topic>`
- `fix/<scope>-<topic>`
- `refactor/<scope>-<topic>`
- `docs/<scope>-<topic>`
- `release/<version>`

## Commit style

- Conventional Commits only.

## Pull request policy

- Protected `main` branch.
- Required CI checks.
- Required review before merge.
- Linear history.

## Tagging and notes

- Semantic version tags (`vX.Y.Z`).
- GitHub Releases as changelog history source.
